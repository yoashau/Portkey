# Portkey

把 Windows 上已经在跑的本地代理，接到 Linux 服务器的本机端口。需要的话，也让那台服务器上新开的终端自动使用它。

它不安装远程代理，不修改别人的进程，也不改你已经打开的终端。

## 开始之前

- Windows 10 或 11，已安装 OpenSSH 客户端。
- 本地代理监听 `127.0.0.1`，常见端口是 `7890`。不必打开局域网访问。
- 能用 SSH 登录目标服务器的普通用户。自动写入终端配置目前只支持 Ubuntu / Debian 和 Bash。

## 第一次使用

1. 运行 `Portkey.exe`。它只出现在托盘里，左键打开，Esc 或点外面收起。
2. 添加连接。可以从已有的 SSH Host 导入。名称与主机会填入；用户名、SSH 端口和私钥仅在配置中写明时填入。未写明的项保持留空，连接时沿用 SSH 配置，不写入系统默认用户或端口 22。
3. 本地代理端口填 Windows 上的代理端口。服务器端口是那台机器 `127.0.0.1` 上的端口，默认 `17890`，范围 `1024–65535`。不要填 SSH 的 `22`。
4. 新主机先点「首次 SSH 认证」，向管理员核对指纹后再确认。加密私钥要先用 `ssh-add` 加入 ssh-agent。程序不保存密码，也不自动接受未知主机密钥。
5. 保存。默认会把代理地址写入你的 Bash 和 systemd 用户环境。如果不想改服务器文件，取消「新终端自动使用此代理」再保存。
6. 回到主页看状态。「代理正常」表示隧道和实际访问都通了。检测用固定地址 `https://www.gstatic.com/generate_204`，预期 204，不用自己改。文件写成功不等于隧道已经通。

## 以后改端口或协议

只在连接设置里改，然后保存。服务器上 Portkey 自己的配置会跟着改。标记以外的内容不会动。

已经打开的终端、已经在跑的服务和 VS Code Server 不会自动换地址。新开一个终端再试。

## 保存后提示「没有同步」

这表示本机设置保存了，但服务器上的自动代理配置没有改。新终端仍会走旧地址，所以可能无法联网。不要把这条提示当成已经生效。

常见原因是你改过 Portkey 写入的那一段。程序不会自动覆盖。确认那是误改后，点同一页出现的「覆盖这段配置并保存」。平时没有这个按钮，也不会自动覆盖。

## 服务器端口被占用

这不是误报。那台机器上已经有程序监听这个端口，新隧道就绑不上去。普通权限的 `ss` 和 `lsof` 可能看不到别人的套接字。

不要结束看不清的进程。换一个没人用的服务器端口，保存即可。若自动配置没能同步，主页会留下警告。

## 不再使用

在连接设置里删除此连接。本机配置会删除，并尝试清除服务器上 Portkey 写入的配置。标记以外的内容保留。服务器暂时连不上时，本机配置仍会删除，提示里会说明远程没有清掉。

## 构建

在 Windows 上运行 `scripts/build.ps1`。产物是 `artifacts/win-x64/Portkey.exe`，该目录不进入版本库。测试记录见 `docs/TESTING.md`。
