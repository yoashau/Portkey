# 授权测试机的持久化部署测试

2026-10-21，Asia/Shanghai。测试者授权在一台自有服务器上清理冲突的旧隧道，并用 Portkey 在 17890 完成首次部署；先临时备份，验证成功后删除备份。主机别名、账号、地址、进程号和本机安装路径不写入仓库。

## 真实变更

测试前由操作者处理与本次端口冲突的旧隧道，以及不再使用的手动代理配置。清理前核对原文件摘要、普通用户所有权和路径。该清理是本次明确授权的一次性准备，产品不会自动删除第三方配置。

关闭服务器上确认没有终端和子进程的旧转发专用 SSH 会话，前后监听对比仅移除 `127.0.0.1:17890`。当时的 Windows 端未发现对应保活进程或计划任务。未终止其他 SSH 会话。

随后通过正式 `SshTunnelManager`、`LinuxDeploymentPlanner`、`LinuxDeploymentExecutor` 执行真实反向转发与五处文件变更：

| 文件 | 变更 |
| --- | --- |
| `~/.config/portkey/proxy.sh` | 新建，导出八项大小写代理变量 |
| `~/.config/environment.d/90-portkey.conf` | 新建，为 systemd 用户进程提供同样的变量 |
| `~/.config/portkey/manifest.json` | 新建，记录配置格式版本、受管文件及配置块摘要 |
| `~/.bashrc` | 追加 Portkey 标记块 |
| `~/.bash_profile` | 追加 Portkey 标记块，保留原有加载 `.profile` 的逻辑 |

本次 `.profile` 在准备阶段清理后不再改动。文件中的 `Portkey managed v1` 和清单 `version: 1` 均表示配置格式版本，不随软件发布版本自动变化。

## 实测结果

测试执行时间 19:58:33–19:58:48；桌面程序于 19:59:02 接管。

- 旧隧道关闭后，远程 17890 无监听；Windows 7890 的 HTTP/SOCKS5 仍实际返回 204，而经 Linux 17890 的两种请求均失败。
- 正式连接管理器在同一端口建立反向隧道，HTTP/SOCKS5 均返回 204，状态 Healthy。
- 五处提交后的内容校验通过；再次生成部署计划为零变更。
- 清除八项继承变量后，新 Bash 登录 Shell 与交互 Shell 均加载正确的八项代理变量。
- systemd 用户管理器的八项变量一致；新启动的临时用户服务确实继承这些变量，测试结束自动回收该服务。
- 新 Linux 登录进程使用 Python 标准库 urllib 的默认代理环境和默认 TLS 证书校验，实际 HTTPS 返回 204。
- 暂停隧道后，17890 释放；持久文件摘要不变，新登录 Shell 仍有代理配置。重新连接后恢复 Healthy。
- 正式 `SettingsStore` 保存该测试别名的自动连接配置，本地 7890 → 远程 17890，Mixed。未修改 Windows 登录自启动设置。
- 从固定目录重启发布版 EXE 后，桌面进程创建 SSH 子进程；桌面日志确认真实 HTTP/SOCKS5 204，独立的新 Linux 登录进程再次返回 HTTPS 204。
- 全部成功后删除远程临时旧配置备份、本次部署生成的备份，以及本地旧配置快照和旧预览；保留本地测试日志。产品今后部署的正常备份机制不变。

持久配置在工具关闭后保留；实际流量需要 Portkey 和 Windows 本地代理运行。已有进程不会自动获得新变量。这轮没有重启服务器，也没有执行真实卸载/恢复验收，不能据此声称覆盖这些场景或鼠标点击操作。

## 日志与入口

- `artifacts/deployment/deployment-test.log`：正式组件的实际部署和验证结果，不包含完整用户启动文件，且不进入版本库。
- `artifacts/deployment/handoff-test.log`：桌面接管、独立请求与临时备份清理记录，不进入版本库。
- `%LOCALAPPDATA%\Portkey\Logs\portkey.log`：持续运行的桌面程序日志。分享前请自行审阅。

显式部署测试入口如下。必须先获得对目标账户的写入授权，并确认目标端口空闲、账户中尚无 Portkey 清单。失败即停止，不能直接在已经完成的部署上重复运行：

```powershell
.\scripts\test-live.ps1 -HostAlias <ssh-host> -RemotePort 17890 -Deploy
```

此入口会保留部署并保存自动连接配置，退出时释放测试隧道，由桌面程序接管。旧配置清理、旧会话终止、桌面接管及删除临时备份是本次单独执行的准备步骤，不由该测试入口自动完成。
